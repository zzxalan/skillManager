# Smart Customer Customization

## 定位

把单客户差异隔离在客户专属 `smart-*-mixed` 插件中，同时复用基座和业务插件的正式能力，避免把客户条件、入口路径或页面逻辑污染到 `smart-core` 和公共插件。

本 skill 只补充“客户定制”特有的架构判断、回退要求和验证策略；通用交付流程归 `smart-project-workflow`，具体 Java/React 实现归后端和前端 standards。

## Core Workflow

1. 先使用 `smart-platform` 通过 MCP 确认基座、客户插件、业务插件、终端和本地仓库映射；以实际仓库代码覆盖过期项目地图。
2. 读取目标仓库 `AGENTS.md`，检查 `git status`、近期提交和已有 `docs/`，建立不覆盖用户改动的事实基线。
3. 使用 `smart-project-workflow` 完成需求、边界、契约、计划、验证和 PR 交付产物。若目标插件尚不存在，使用 `init-smart-plugin` 初始化 mixed 插件，禁止手工拼装另一套模板。
4. 把每项需求归入以下一种类型：
   - 仅客户需要的入口、编排、页面或适配：放入客户插件。
   - 可复用且属于某业务域的能力或缺陷：归数据/能力所属插件，不因本次定制复制实现。
   - 真正通用的基座扩展：只有形成稳定公共契约并得到明确确认后才修改 `smart-core`。
   - 暂时禁止修改所属插件的需求：记录缺口、风险和待办，不在客户插件跨表或绕过鉴权补洞。
5. 涉及入口接管、跨插件调用、权限或数据时，读取 [boundary-and-contract.md](references/boundary-and-contract.md)，先写清原契约、定制差异、恢复条件和失败语义，再编码。
6. 采用“最小响应变换 + 生命周期回退”：尽量让宿主或所属插件继续完成查询、权限过滤、签名和业务校验，客户插件只修改获批的差异；停用插件后必须自然恢复原行为。
7. 后端实现使用 `smart-backend-standards`；前端/H5 实现使用 `smart-frontend-standards`；全栈、打包或联调同时使用两者。不要在本 skill 中自行定义第二套代码规范。
8. 开发和交付时读取 [verification-matrix.md](references/verification-matrix.md)，按静态检查、单元/契约、构建、包内容、Mock、只读现场、获批真实操作和回滚分层留证。
9. 交付前更新 `docs/spec.md`、`design.md`、`data-ownership.md`、`plan.md`、`verification.md`、`pr-description.md`。完成结论必须区分已验证、待现场验证和明确不做。
10. 需要了解本 skill 的来源和适用边界时，读取 [znmzdx-case-study.md](references/znmzdx-case-study.md)；不得把案例中的客户常量当成新项目默认值。

## Hard Gates

- 未证明是公共能力且未获明确确认，不修改 `smart-core` 或公共业务插件来承载单客户差异。
- 未完成数据归属判断，不新建影子表、不跨插件直接读写表、不复制另一个插件的领域数据。
- 未写清原入口的登录、签名、权限、数据范围和返回契约，不接管或转发原接口。
- 不以 H5 隐藏按钮代替后端鉴权；不把权限失败、接口失败、未配置和设备离线合并成同一状态。
- 定制路径、拦截器、资源和后台任务必须随插件生命周期注册与注销；停用插件后不得残留全局影响。
- 高危设备操作、密码修改、生产发布或故障注入未经单独授权，只能做 Mock、只读检查或记录待验证项。
- 未检查最终插件包中的前端资源、入口文件和关键后端类，不宣称打包完成。

## 定制设计原则

- 优先独立客户插件，优先正式扩展点和正式调用链，最后才考虑原接口接管。
- 入口接管只变更必要字段，保留名称、图标、排序、权限、PC/H5 分组和其他应用。
- “客户端仍走原接口”表示外部方法、路径、认证和响应契约保持不变，不表示该入口无需参与定制。凡是必须收到定制路径的 Web、H5、小程序或第三方渠道，都要先确认其实际应用列表接口，再逐条纳入最小变换；同一接口返回 PC 与 H5 数据时只改目标 H5 字段。
- 复用宿主 Bean 时明确 MAIN/PLUGIN 边界；复用其他插件能力时使用其正式 Supplier、OpenAPI、Extract 或公开接口，不直接访问实现表。
- 外部入口经过的认证只执行一次。内部转发目标必须拒绝外部直连，且不能因为免登录注解形成免签或匿名入口。
- 独立 H5 的生产 `base`、输出目录、后端资源复制目录和最终访问路径必须形成一条可核对链路。
- 页面先同步宿主设置和当前账号权限，再渲染依赖主题或权限的内容；弹层挂到 `body` 时，把主题变量写到根节点。
- 主色跟随宿主主题；在线、警告、离线和危险操作继续使用语义色，避免业务状态随客户主题失真。
- 对 `unknown`、空对象、残缺字段等状态先确认所属插件契约；未知不等于失败，未配置不等于无权限。

## 交付摘要

最终至少说明：

- 定制差异位于哪个客户插件，哪些仓库保持未修改。
- 复用了哪些宿主或业务插件契约，谁拥有数据与最终鉴权。
- 插件加载时改变什么，停止后如何恢复。
- 已完成哪些本地、包级和现场验证，哪些高风险项仍待授权。
- 回滚是否只需停用/移除客户插件，是否涉及数据恢复。
