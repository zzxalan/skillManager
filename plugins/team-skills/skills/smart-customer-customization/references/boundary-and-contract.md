# 客户定制边界与契约检查

## 1. 归属决策

| 需求特征 | 默认落点 | 处理原则 |
| --- | --- | --- |
| 客户专属名称、入口、页面、流程编排、第三方适配 | 客户 mixed 插件 | 不向基座散落客户判断；插件停用后恢复标准行为。 |
| 可被多个客户复用的业务能力 | 数据/能力所属业务插件 | 形成正式接口或扩展点，客户插件只消费。 |
| 插件装载、公共认证、公共权限、公共运行容器能力 | `smart-core` | 只有明确通用需求才修改，禁止为单客户设计抽象注册中心。 |
| 另一个插件的缺陷，但本次不允许修改它 | 所属插件待办 | 客户插件不得跨表、复制领域逻辑或放宽权限作为补丁。 |
| 设备厂商、校园平台或客户系统适配 | 客户插件或专用适配插件 | 对内保持 smart 正式契约，对外隔离厂商差异。 |

出现争议时先回答：差异删除后，剩余能力是否仍对其他客户有价值？若没有，默认不进入公共仓库。

## 2. 数据与调用边界

为每个读写项记录：

- 数据所有者：基座、业务插件、客户插件或外部系统。
- 正式调用入口：MAIN Bean、Supplier/OpenAPI、Extract、HTTP 接口或消息事件。
- 调用方向与失败语义：不可用、无权限、未配置、离线、未知、超时如何区分。
- 鉴权责任：入口鉴权、数据范围、操作权限和设备归属分别由谁校验。
- 降级策略：失败时是否允许只读、隐藏、明确报错或回退标准入口。

禁止以下捷径：

- 直接读写其他插件表或复制其表到客户插件。
- 根据前端传入的房间、设备或用户标识跳过后端归属校验。
- 把另一个插件返回的权限错误归一成“没有数据”或“未设置”。
- 因供应方状态字段不稳定就在客户插件发明新的含义；先核对供应方契约和实际样本。

## 3. 原接口接管

只有在客户端必须保留原路径、现有扩展点不足且停用可恢复时，才接管原接口。

接管前建立原契约清单：

- HTTP 方法、路径、请求体、响应结构和错误码。
- 登录、签名、nonce、防重放、权限列表和数据范围。
- PC、H5、小程序、第三方入口是否使用不同接口。
- 原处理链中哪些步骤必须在转发前执行，哪些服务可在插件内复用。

需求中的“继续使用原接口”通常要求客户端调用方式不变。若该客户端需要看到定制入口，客户插件仍需在服务端对这条真实调用链做最小变换，同时完整保留原方法、路径、签名、权限过滤和响应结构。不要把“保留原接口”误解为“不处理这个渠道”。

实现时遵守：

1. 使用插件生命周期管理的拦截器或正式扩展点，不修改宿主 Controller 来写客户条件。
2. 原路径与内部目标路径必须不同，避免递归。
3. 保留原入口的认证步骤；需要内部转发时，使用仅服务端可设置的请求上下文标记限制目标接口直连。
4. 内部接口即使免登录，也不能形成免签或匿名公网入口。
5. 先调用宿主/所属插件的正式服务得到已过滤结果，再做最小响应变换。
6. Web、H5、小程序、第三方等需要获得定制入口的渠道必须逐条覆盖；PC 不变应通过只保留 PC 字段来实现，不能通过漏掉整个共享接口实现。
7. 为目标、非目标、空结果、多个入口和插件停止回退编写测试或集成验证。

## 4. 独立 H5 与资源链路

核对四个位置是否一致：

```text
客户端入口路径
  -> Vite production base
  -> frontend/dist/<h5-subdir>
  -> 插件包 web/<h5-subdir>
```

同时确认：

- URL token/cookie 只在既有登录链路需要时同步，不记录或输出 token。
- 当前账号权限从宿主权威接口加载；本地缓存只能作为缓存，不能作为唯一权限来源。
- 宿主主题在首次渲染前同步；Ant Design 与 antd-mobile 使用同一主题桥接。
- Popup/Modal 等 portal 内容能从 `document.documentElement` 继承主题变量。
- H5 路由、basename/hash、插件 ID、资源路径和后端复制目录相互匹配。

## 5. 回退设计

设计时直接写出停用客户插件后的结果：

- 原接口是否自动恢复宿主实现。
- 原应用入口是否恢复标准路径。
- 是否有数据库、缓存、定时任务、拦截器或资源残留。
- 外部系统是否需要撤销回调或配置。

若回退需要修改基座、手工修表或删除共享数据，说明隔离设计尚未完成，必须重新评审。
