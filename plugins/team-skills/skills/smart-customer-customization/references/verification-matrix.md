# 客户定制验证矩阵

## 分层验证

| 层级 | 最低证据 | 重点 |
| --- | --- | --- |
| 仓库基线 | `git status`、相关提交和受影响仓库清单 | 证明未覆盖用户改动，公共仓库是否保持干净。 |
| 静态检查 | 后端编译、前端 lint/typecheck | 契约类型、路由、配置、格式和明显错误。 |
| 单元/契约 | 目标与非目标、权限分支、状态边界、错误语义 | 最小变换，不误伤标准行为。 |
| 构建 | 后端 build、PC/H5 生产 build | 独立 H5 与 mixed 插件同时可构建。 |
| 包内容 | 解包或列出最终 JAR | 关键类、`resources.json`、`web/.../h5.html` 和静态资源存在。 |
| Mock 页面 | 移动端视口、主题、权限、空/残缺/异常状态 | 可重复覆盖交互，不触碰真实设备。 |
| 只读现场 | 应用列表、静态入口、页面查询、主题与权限加载 | 使用真实契约和数据，不改变设备或密码。 |
| 获批真实操作 | 门锁、空开、班牌、密码、发布与故障注入 | 每类操作需单独授权、明确目标和恢复方式。 |
| 回滚 | 停用/移除插件后的接口与入口 | 标准行为恢复，无残留全局影响。 |

## 必测契约

- 只修改目标客户、目标分组、目标应用或目标页面。
- 非目标 H5、PC 路径、名称、图标、排序、权限和其他字段不变。
- Web、H5、小程序和第三方若有不同入口，逐条确认实际调用链；“仍走原接口”必须同时验证外部契约未变且定制路径确实返回。
- 内部转发目标拒绝外部直连；原入口的登录、签名和数据权限仍生效。
- 插件不加载或停止时，客户端回到标准实现。
- 无权限、接口失败、未配置、明确离线和未知状态分别显示与处理。
- 高危操作有二次确认，离线设备不可操作，服务端仍做最终校验。

## H5 专项

- 生产入口可访问且静态资源无 404。
- URL 查询参数不会破坏本地 history fallback 或生产 hash 路由。
- 修改宿主 `colorPrimary` 后，Tab、选中态、按钮、底部导航和 portal 弹层同步变化。
- 明暗背景下卡片、文字、边框、禁用态可读；成功、警告、错误语义不被主色覆盖。
- 有权限与无权限账号分别验证操作入口；查询失败不能伪装成未设置。
- 设备名缺失、空对象、残缺字段、状态 `unknown` 等契约边界有测试。

## 现场安全分级

默认可执行：

- 静态资源访问、GET/只读查询、页面浏览、Mock、构建和包检查。

需要明确授权：

- 真实设备控制、密码新增/修改、权限配置、生产发布、插件停止、故障注入、缓存清理和外部消息发送。

未经授权时，把对应场景标记为“待现场验证”，记录环境、账号类型、所需前置数据和预期结果，不用“跳过”冒充“通过”。

## 完成判定

交付结论必须分别列出：

- 已通过：附命令、测试名、包内容或现场响应证据。
- 待现场：说明为什么本轮不能安全执行，以及谁需要授权。
- 不做：说明数据/能力归属和独立需求落点。
- 回滚：说明停用插件能恢复哪些行为，是否仍有人工步骤。
