# 测试用例输入与标准化

## 输入源决策

### 飞书链接

1. 识别链接实际指向飞书文档、表格或其他可访问页面。
2. 优先使用适用的飞书连接器；没有连接器时再使用具有现有登录态的浏览器或 Chrome。
3. 检查链接权限、页面是否完整加载、表格是否折叠以及是否存在分页或嵌入内容。
4. 保留来源链接和章节、表格标题或可定位的上下文。
5. 权限不足时要求用户授权，或提供对应 Excel 文件；不要用搜索引擎寻找替代内容。

### Excel 文件

1. 支持 `.xlsx` 和 `.xls`，以只读方式读取，不修改或重新导出源文件。
2. 扫描全部工作表，识别测试用例表、说明表、字典表和空白表。
3. 自动处理标题行、空行、合并单元格和同一用例跨多行记录步骤的情况。
4. 多个工作表都包含有效用例时默认全部解析，并按工作表保留来源位置。
5. 无法判断有效工作表或表头时，只询问工作表名和表头行等最小必要信息。

### 同时提供两种来源

- 不要默认合并飞书与 Excel。
- 先确认权威版本，或者确认用户是否要求对比差异。
- 用户要求对比时，先按用例编号匹配，再比较步骤、数据和预期结果；冲突项必须显式列出。

## 字段识别

常见列名按下表归一化；允许同义词，不要求源文件严格使用固定表头。

| 标准字段 | 常见来源列名 |
| --- | --- |
| `caseId` | 用例编号、用例ID、ID、Case ID |
| `module` | 模块、功能模块、所属功能、菜单 |
| `title` | 用例标题、用例名称、测试项、场景 |
| `preconditions` | 前置条件、前提、准备条件 |
| `role` | 账号、用户、角色、权限角色 |
| `testData` | 测试数据、输入数据、参数 |
| `steps` | 操作步骤、测试步骤、步骤 |
| `expectedResults` | 预期结果、预期、期望结果 |
| `priority` | 优先级、级别、Priority |

没有单独 `title` 时，可以用首个明确的业务场景短句作为标题，但不得改写业务意图。

## 标准用例模型

对每条用例至少保留：

```text
sourceType        feishu | excel
sourceLocation    飞书链接+章节，或 Excel 文件名+工作表+行号
caseId            原始用例编号；没有时生成稳定的临时编号并标记来源缺失
module            smart 业务模块或菜单
title             用例标题
preconditions     前置条件列表
role              账号角色和权限要求
testData          输入、已有数据和需创建数据
steps             有序操作步骤
expectedResults   与步骤对应的预期结果
priority          原始优先级
notes             假设、疑点和来源备注
```

## 多行与合并单元格处理

- 合并单元格的值向其覆盖的用例行传播，但不要跨越下一个明确用例编号。
- 一条用例的多个步骤分布在多行时，按原始行序和步骤编号排序。
- 预期结果分布在多行时，尽量与同一行或同编号步骤配对；无法配对时标记疑点。
- 空白用例编号行只有在上下文明确属于上一条用例时才合并。
- 重复用例编号不能静默覆盖；保留全部记录并标记冲突。

## 完整性判断

以下缺失属于硬阻塞：

- 无法访问或读取输入源。
- 无法识别任何有效测试用例。
- 缺少关键操作步骤。
- 缺少可验证的预期结果。
- 无法确定目标测试环境。

以下信息优先从系统、代码或上下文推断，无法推断时再询问：

- 账号角色。
- smart 插件归属。
- 测试数据来源。
- 菜单路径和页面路由。
- 优先级。

不得自行创造关键业务预期。对不影响业务判断的格式差异和说明性缺失，可以记录假设后继续。

## 可追踪性

- 测试标题使用 `[caseId] title`。
- 飞书来源保留原始链接和章节或表格说明。
- Excel 来源保留文件名、工作表名和原始行号范围。
- 一个用例拆成多个 Playwright 测试时，使用相同 `caseId` 加清晰后缀。
- 多个用例合并成场景测试时，必须在注释或 annotations 中列出全部来源编号。
